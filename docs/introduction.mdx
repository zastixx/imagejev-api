Vision-Language models (VLMs) are designed to produce text for humans to read. When you need a model to make a judgment that your software will consume, that creates a mismatch: you are coercing a slow text-generation system into outputting structured tokens, then parsing the results back into something your code can depend on.

ImageJev is the flagship model and the first **System One Vision model**. System One models are built to make fast, structured decisions that software can use directly. ImageJev evaluates typed *questions* against an image or raw pixels and returns structured results directly. No token generation, no parsing. You get typed values and probability distributions that your code can branch on, sort by, and route with. Choice and Score also return **confidence**, which your code can use to decide whether and how to act on an answer.

## ImageJev primitives

ImageJev exposes three *AI primitives*. Similar to software primitives, our AI primitives are modular, composable, structured, reliable, and fast. Each asks a different type of *question* and returns a different type of answer.

| Question type | Goal | Returns |
| :--- | :--- | :--- |
| [Choice](/primitives/choice) | Choose an option from a closed schema | `choice`, `probabilities`, `confidence` |
| [Score](/primitives/score) | Score the image on an ordinal rubric | `score`, `probabilities`, `confidence` |
| [Noul](/primitives/noul) | Is this statement true? (0 to 1) | `probability` |

All three *question* types can be evaluated in high-throughput batches. Every question is evaluated in parallel and in isolation against the same image embedding in one matrix multiply. Adding questions barely changes the response time.

## Atomic questions, composed in code

System One models work best when each question asks one specific, well-scoped visual determination: the kind of judgment a knowledgeable person could make in a fraction of a second given the image.

If the judgment you want to make would weigh multiple independent visual factors, decompose it. Ask each factor as a separate question, then combine the results with business logic in your code. This keeps each evaluation reliable, fast (<15ms on GPU), and gives you full control over how dimensions are weighted.

For example, instead of *"rate this product listing"*, ask separately about:
1. Sharpness & focus
2. Studio lighting vs amateur snap
3. White background presence

Combine the scores with your own formula. When business criteria change, update a coefficient in your code rather than rewriting a prompt.
